# 임베딩에 모순 정보가 남아 있는가 — 프로브 실험

인코더 `intfloat/multilingual-e5-large-instruct` (**얼림**) · MNLI 학습 60000쌍 · dev 3000쌍 · run04 경계 1003개

`embed_check.py` 가 기각한 것은 임베딩이 아니라 **코사인**이었다. 코사인은 두 벡터를 스칼라 하나로 접고 그 축은 주제 유사도에 정렬돼 있다 — 극성이 `|u−v|` 나 `u∘v` 에 남아 있다면 문제는 표현이 아니라 읽는 방법이다. 인코더를 얼린 채 헤드만 MNLI 로 학습해 그것을 가른다.

## 판정

**모순 정보는 벡터에 남아 있다.** 코사인만 쓰면 3-way 정확도 0.4403 / 모순 AUC 0.723 인데, 같은 얼린 벡터에서 `full` feature + mlp 헤드는 0.7193 / 0.8988 로 오른다. 코사인이 정보를 **버리고 있었다**.

**그러나 교차 인코더와의 격차가 남는다: +0.197** (0.7193 vs 0.916). 모순 AUC 로 보면 0.8988 vs 0.9906 인데, **오류율로 환산하면 0.101 vs 0.009 — 11배다.**

원인은 구조다. bi-encoder 는 두 문장이 **풀링 전에 서로를 못 본다**. 모순은 *특정 명제 쌍 사이의 관계*라 어느 토큰이 어느 토큰과 충돌하는지를 봐야 하는데, 고정 길이 요약 두 개로 접은 뒤에는 그 정렬이 남아 있지 않다. 헤드를 키워도 (`linear` → `mlp`) 표현에서 이미 잃은 것은 복구되지 않는다 — 실제로 `full` 에서 헤드를 키운 이득은 정확도 +0.03 에 그쳤다.

**부호는 뒤집혔다.** `embed_check.py` 에서 코사인의 관문 신호는 **음수**였다(잘못 자른 방출이 안전한 방출보다 참조에 더 가깝게 나옴). 여기서도 `cos` 는 -0.0138 로 여전히 음수지만, `diff` 는 +0.1456 로 **양수가 된다.** 방향 문제는 feature 로 해결됐고 남은 것은 정밀도다 — 평균은 맞는데 케이스별로 틀린다.

**관문은 어느 구성도 통과하지 못했다** (최선 2/6, 코사인 단독은 5/6). 통과 기준이 평균이 아니라 **케이스마다** `min(premature) > max(safe)` 라, 평균 격차가 양수여도 한 케이스만 뒤집히면 탈락한다. 목적함수에 들어가는 값이라 그 엄격함이 맞다.

**남은 격차에는 도메인 이동도 섞여 있다.** 프로브는 MNLI(완결된 문장 쌍)로 배웠는데 우리 hypothesis 는 **미완성 조각**이다. 우리 분포로 학습하면 나아질 여지가 있으나, 지금 가진 라벨은 판정자 판정 21건(그중 premature 1건)뿐이라 학습이 불가능하다. 루프가 이터레이션마다 판정을 쌓으므로 나중에 다시 볼 만한 경로이고, 그때도 위의 **구조적 격차**는 그대로 남는다는 점을 감안할 것.
