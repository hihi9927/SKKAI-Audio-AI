## 🔧 작업 내용

### context scoring 모듈 신설 (`research/context_scoring/score_context.py`)
- LibriSpeech 평가 결과(metric.json)를 챕터 단위로 묶어 GPT로 번역 문맥 일관성을 0~100점으로 채점하는 스크립트 작성
- 챕터별 (src, tgt) 쌍을 `1. [EN] → [KO]` 형식으로 포맷해 GPT에 전달
- 6가지 평가 기준 적용: 지시 대명사 연속성, 용어 일관성, 주제 응집성, 문맥적 단어 선택, 서사 연속성, 어조/문체 일치
- 점수는 5점 단위 참조점 기반으로 부여 (0 / 25 / 50 / 75 / 100)
- 여러 metric.json 비교 모드 지원, 결과를 `comparison.json`으로 저장
- 기본 모델: `gpt-5.4-mini`, 기본 동시 요청 수: 3

### context window 파라미터화
- `core/correct_and_trans.py`: `GPTTranslator`에 `max_context` 파라미터 추가
- `Qwen3-ASR/examples/streaming_websocket_server.py`: `StreamingConfig`에 `context_window` 필드 추가, `--context-window` CLI 인자 추가
- `evaluation/LibriSpeech/servers/streaming_websocket_server_fcl.py`: FCL 서버에도 동일 인자 연동
- `evaluation/LibriSpeech/servers/test_qwen3_librispeech.py`: `--gpt-translation`, `--context-window`, `--correction`, `--correction-model`, `--translation-model`, `--api-key` 인자 추가

### server config meta 기록
- `hello` WebSocket 메시지에 `serverConfig` 딕셔너리 추가 (model, chunk_size_sec, enforce_eager, enable_gpt_translation, translation_model, context_window, enable_correction, correction_model)
- 테스트 스크립트에서 `fetch_server_config()` 함수로 세션 시작 시 서버 config를 수집해 `meta.json`에 기록

### FCL 서버 encode_sec / decode_sec null 버그 수정 (`streaming_websocket_server_fcl.py`)
- 원인: `_process_slot_updates`가 `model.generate()` 미실행 시에도 호출되어 `decode_start_elapsed_sec=None`으로 `_slot_seg_detected`를 선점, 이후 실제 `on_seg` 콜백에서의 올바른 타이밍 기록이 차단됨
- 수정: `if t0 is not None:` 블록 내에 `if "<SEG>" in raw_text:` 조건 추가 — state.text에 SEG 토큰이 없으면 기록 건너뜀

## 📊 결과 / 수치

context window 크기별 context score 비교 (LibriSpeech, 18 챕터):

| 설정 | avg_context_score | pairs |
|---|---|---|
| context=5 (run_02) | 52.83 | 982 |
| context=50 | 51.72 | 990 |
| context=20 | 50.94 | 985 |
| GPT 없음 (chunk2.0 baseline) | 41.11 | 1033 |

- context window를 늘려도 점수가 유의미하게 오르지 않음
- context=5가 최고 성능 → 기본값 5 유지가 합리적
- 오류 전파 리스크를 고려하면 window를 작게 유지하는 것이 유리

## 🐛 발견된 문제 및 해결

**SEG 커밋에서 encode_sec / decode_sec가 null로 기록되는 문제**

- 원인: base server 599번 줄의 post-transcribe `_process_slot_updates` 호출이 `model.generate()` 미실행 상태에서도 발동되어 `_slot_seg_detected[key]`를 잘못된 타이밍(`decode_start_elapsed_sec=None`)으로 선점
- 해결: FCL 서버의 `_process_slot_updates` 내 `if t0 is not None:` 블록에 `if "<SEG>" in raw_text:` 가드 추가. `elif t0 is None:` (VAD 경로)에는 이미 동일한 가드가 있었으나 streaming_transcribe 경로에 누락되어 있었음
