## 🐛 발견된 문제 및 해결
- 모드2(always-commit) 여부는 기존 `hello.serverConfig`에 노출되지 않아 클라이언트가 원격 서버의 실제 설정을 검증할 방법이 없었음 → 서버 쪽에 필드 2개 추가해서 해결.
- `eval-run.md`가 예전 AWS EC2 인프라(aws_dev/aws_app/aws_test 인스턴스) 기준으로 작성돼 있었으나, 실제로는 온프레미스 4090 GPU 박스로 운영이 옮겨간 상태라 문서와 실제 구성이 어긋나 있었음 → 섹션 2를 실제 구성에 맞게 재작성.
- 문서상 conda env 이름(`qwen3-asr`)이 실제 서버 env 이름(`stity`)과 불일치 확인 → 섹션 4/5 명령어 전체 수정.
- `gpu` SSH alias가 실제로는 `~/.ssh/config`에 존재하지 않음을 확인. 처음엔 `skkai_4090_vpn`(13.209.199.242)을 GPU 서버로 추정했으나, 실제 점검 결과 GPU 없는 별도 EC2(VPN 중계용 추정)로 판명 — 진짜 GPU 서버는 이 세션이 SSH로 접속해 있는 로컬 박스 자체였음.
- loopback(`ssh gpu` → localhost) 자체인증을 시도했으나, 이 박스의 `authorized_keys`엔 팀원 노트북들의 공개키만 등록돼 있고 이 박스 자신의 공개키는 없어 `Permission denied (publickey,password)`로 실패. alias를 실제로 동작시키려면 config 추가와 공개키 등록(authorized_keys) 두 가지가 모두 필요하다는 점 확인.
- `/eval-run`과 `paper_result/ASR/scripts/*.sh`가 완전히 분리된 채 서로를 참조하지 않고 있던 문제 발견 → 스크립트는 재현 가능한 실행 아티팩트로 그대로 두고, `/eval-run`이 이를 호출하도록 연동(스크립트 내용을 문서에 인라인 통합하지는 않기로 결정).

## ⏭ 해결되지 않은 작업
