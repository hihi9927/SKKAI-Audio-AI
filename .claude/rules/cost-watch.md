# 비용은 항상 추적 가능해야 한다

API 비용은 팀이 직접 부담한다. 돈이 드는 실행에서는 아래 둘을 모두 지킨다.

## 1. 추적 수단 없이 돈 쓰지 않는다

**비용이 발생하는 코드·스크립트를 새로 쓸 때는 그 비용을 나중에 집계할 수 있는 수단을
반드시 함께 넣는다.** 추적 수단이 없으면 그 실행은 시작하지 않는다.

최소 요건:

- 호출마다 usage(입력·출력 토큰, 모델명)를 기록한다. 응답만 저장하고 usage 를 버리지 않는다.
- 기록은 **중간에 죽어도 남아야 한다.** 끝날 때 한 번에 쓰면 크래시한 런의 지출이 통째로
  사라진다. 반복 단위마다 append 하거나 로그에 그때그때 남긴다.
- 로그에 누적 추정 비용을 주기적으로 찍는다. 산출물이 사라져도 로그로 복원된다.
- 집계는 `python -m core.meaning_segmentator.autoseg.cost_report --run-id <id> [--budget N]` 로 한다.
  새 파이프라인을 만들면 이 형태로 집계되게 맞춘다.

기존 파이프라인 주의: `iter_*/metrics.json` 의 usage 는 **런 누적값**이라 런당 최댓값만
취해야 하고, 로그의 "게이트웨이 추정 비용" 값과 비교해 큰 쪽을 쓴다. 분절 캐시 건수와
기록된 분절 수의 차이가 곧 기록되지 않은 지출이다.

**크래시 후 재실행할 때 이전 로그를 지우지 않는다.** 지우면 그 실행의 비용은 영영 복원 못 한다.

## 2. 예상보다 $5 넘게 초과하면 멈추고 원인을 가린다

기준선은 그때까지 누적된 실지출이다. 초과를 감지하면 계속 태우지 말고 셋 중 무엇인지
가려서 보고한다:

1. 버그 때문인가
2. 줄일 수 있는데 안 줄이고 있는가
3. 불가피한가

**비용 초과는 대개 낭비가 아니라 버그의 증상이다.** 실제로 데이터 검증을 건너뛴 탓에
FLEURS TSV 따옴표 파싱 버그로 2,916어절짜리 잔해가 표본에 섞였고, NLI 백엔드의 512토큰
한계를 넘겨 런이 죽으면서 $3.5 를 날린 사건이 있다.

## 지킬 것

- 큰 배치 전에 **데이터 위생 검사 먼저** — 길이 분포(최대·평균), 행 수, 이상치 표본 출력.
  스모크 테스트는 표본이 작아 이상치를 놓친다 (20문장 스모크가 위 버그를 못 걸렀다).
- 비용을 줄이는 레버는 모델 > `--seg-reasoning-effort` > `--batch-size` 순이다.
- Google gtx 무료 엔드포인트 번역은 비용 0 이다.
