# 오래 도는 작업은 tmux 로 격리한다

라벨링·번역·평가 체인처럼 몇 분 이상 도는 작업은 에이전트의 백그라운드 실행
(`run_in_background`)으로 띄우지 말고, **반드시 tmux 세션으로 띄운다.**

```bash
tmux new-session -d -s <이름> -c /path/to/repo "bash <스크립트>"
```

## 왜

백그라운드 작업은 `claude` 프로세스의 자식으로 붙는다. VS Code 창을 닫거나 세션이
끝나면 부모가 죽으면서 자식 bash 가 전부 딸려 죽는다.

2026-09-02 00:45:06 에 체인 4개(zh 재라벨링 / en→X bleu_eval / COMET·그래프 / X→en)가
같은 초에 동시에 끊겼다. OOM 도 재부팅도 아니었고, 세션 마지막 기록 시각과 마지막 파일
쓰기 시각이 일치했다. 같은 머신에서 tmux 로 띄운 세션만 살아남았다. tmux 는 자기 데몬에
붙으므로 claude 의 자식이 아니다.

`/etc/systemd/logind.conf` 의 `KillUserProcesses=no` 나 `Linger=yes` 로는 못 막는다.
그건 logind 가 세션 스코프를 정리하지 않는다는 뜻일 뿐, 부모가 죽을 때 자식이 거둬지는
경로와는 무관하다. 이걸 근거로 "그냥 둬도 계속 돈다" 고 판단하면 틀린다.

## 지킬 것

- 체인은 스크립트 파일로 떨궈서 위 형태로 띄운다. 인라인 명령을 길게 쓰지 않는다.
- **PID 로 선행 작업을 기다리지 않는다.** 세션이 죽으면 PID 가 무의미해진다. 마커 파일로 순서를 잡는다.
- tmux 서버는 기존 환경을 물고 있어 `OPENAI_API_KEY` 같은 값이 없다.
  스크립트 안에서 `set -a; . ./.env; set +a` 로 직접 읽는다.
- 진행 상황은 로그 파일로 본다. 파이썬은 `-u` 를 붙여야 버퍼링 때문에 로그가 0바이트로 보이지 않는다.
